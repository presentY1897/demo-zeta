## 배포 스모크 (완료 기준)

1. web 접속 → 데모 계정 원클릭 로그인
2. 신규 가입(별도 시크릿 창) → 플롯 생성(공개) → 데모 계정 홈에서 그 플롯 확인. Google 로그인도 1회 왕복
3. 모의 모드 채팅 → 새로고침 후 대화 유지 → 중단 시 부분 보존
4. (선택) BYOK 키로 실제 프로바이더 1회
5. office 접속 → admin 로그인 → 공지 작성 → web에 반영 확인
6. office 유저 목록에서 2번의 신규 계정 검색 → 제재 → 해당 계정 로그인 차단 확인 → 해제
7. 대시보드 오늘 날짜에 3번 채팅의 턴·DAU 반영 확인

## 테스트

- [ ] 위 배포 스모크 체크리스트는 수동으로 1회 병행(E2E가 못 덮는 BYOK 실 프로바이더·구글 로그인)

## 구현 노트

- 시드는 배포 파이프라인이 아니라 **로컬에서 1회 수동 실행** — 서버리스 빌드 단계에서 DB를 만지지 않는다.
- Vercel의 함수 리전과 Neon 리전을 맞춘다(레이턴시). 둘 다 아시아(도쿄/싱가포르) 권장.
- `x-accel-buffering: no` 등 기존 스트리밍 헤더는 Vercel에서도 유효 — 배포 후 스트리밍이 버퍼링되지 않는지 3번에서 확인.
- 실패 시 롤백은 Vercel 이전 배포 승격으로 충분(DB 마이그레이션은 초기 1회라 롤백 시나리오 없음).

## 오피스 접근 결정 (09-01)

**배포된 오피스 비밀번호를 README에 공개한다.** 애초 계획은 "비밀번호는 README에 쓰지 않음"이었지만,
저장소가 public이라 기본값 `theta-office`는 이미 공개돼 있고(`.env.example`·`e2e/env.ts`),
무엇보다 **오피스는 이 데모의 절반이라 리뷰어가 클릭 한 번으로 들어가지 못하면 안 본다**.

대신 두 가지로 감수 가능한 위험으로 만든다.

- **오피스 안에 "데모 초기화" 버튼**(대시보드 하단) — `pnpm db:seed`와 같은 함수를 호출하는
  admin 전용 엔드포인트(`POST /api/admin/demo-reset`). 누가 데이터를 흐트러뜨려도 화면 안에서
  5초면 시드 직후 상태로 돌아간다. 즉 최악의 피해가 "누가 리셋함"으로 줄어든다.
- README에 **"공개 데모이므로 누구나 오피스에 들어올 수 있고, 데이터는 언제든 초기화된다"**를 명시한다.

대안이던 "배포본만 열람 전용(DEMO_READONLY)"은 기각했다 — T5의 오피스→웹 즉시 반영과
T6의 제재 효력이 이 프로젝트의 시연 포인트인데 그걸 배포본에서 못 보여주게 된다.

E2E는 붙이지 않았다 — 초기화가 DB를 통째로 비워 같은 스위트의 다른 시나리오와 충돌한다.
통합 테스트 3개(빈 DB 채우기·흐트러진 상태 원복·비인증 401)로 덮었다.
