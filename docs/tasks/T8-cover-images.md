# T8 — 커버 이미지 업로드

- 상태: 대기 · 브랜치: `feature-cover-images` · 의존: T3 · 커밋 계획: 2개 — 업로드·서빙 API / 위저드·표시 전환
- 슬롯: T3 이후 아무 때나(다른 티켓과 독립). **T7 배포 전 권장**, 밀리면 09-02에 하고 재배포
- 설계 근거: [server-design.md](../server-design.md) §2(스키마)·§4(API)

## 목표

만들기에서 이모지 대신 **실제 썸네일 이미지**를 올릴 수 있다. 업로드한 플롯은 홈 카드·프로필·
채팅 아바타·대화 목록에 이미지로 보이고, 안 올리면 기존 이모지+그라디언트가 그대로 폴백이다.

## 범위

- **포함**: images 저장·업로드/서빙 API, 위저드 업로드 UI(클라이언트 리사이즈), 표시 컴포넌트 전환
- **제외**: 기존 플롯의 이미지 교체(수정 화면 자체가 스코프 외), 이미지 검수/신고(README 한계 명시), 외부 오브젝트 스토리지 연동(인터페이스만 분리)

## 저장 방식 결정

**DB(bytea) 저장 + 스토리지 인터페이스 분리** — 데모 조건에서의 선택.

- 외부 서비스·env 키 없이 로컬 docker와 Neon에서 **동일하게 동작**(env 가이드 원칙과 일관 — 키 없는 로컬 실행 유지)
- 클라이언트 리사이즈 후 ~200KB 수준이라 데모 규모에서 Neon 무료 티어(512MB)로 충분
- 코드에서 저장 접근을 `save/get` 인터페이스로 분리해, 실서비스라면 오브젝트 스토리지+CDN으로
  교체되는 지점임을 구조로 보여준다(README 한계에도 명시)
- 대안이었던 Vercel Blob은 더 실서비스답지만 로컬에 토큰(env)이 필요해지고 외부 종속이 늘어남 — 기각

## 작업 항목

### 업로드·서빙 API (커밋 1)

- [ ] 스키마 추가(T1의 스키마에 편입) — `images`: id uuid PK · owner_id FK · content_type · bytes bytea · width · height · created_at / `plots.cover_image_id` FK 널 허용
- [ ] `POST /api/uploads` — 로그인 필수, multipart. 서버 검증: **매직 바이트**로 jpeg/png/webp 확인(확장자·Content-Type 헤더 불신), 2MB 상한(413), 픽셀 크기 상한. 응답 `{id}`
- [ ] `GET /api/images/[id]` — bytea 응답, `Cache-Control: public, max-age=31536000, immutable` + ETag, 없는 id 404
- [ ] `POST /api/plots`가 `coverImageId` 수용 — 본인이 올린 이미지만 연결 가능(타인 이미지 id 거부)
- [ ] 저장 접근 `save/get` 인터페이스 분리(구현체는 DB)

### 위저드·표시 전환 (커밋 2)

- [ ] 위저드 1단계에 **커버 이미지 필드(선택)** — 파일 선택 → canvas로 4:3 크롭·최대 800×600 리사이즈·webp 재인코딩(EXIF 제거 겸, ~0.8 품질) → 미리보기 → 제출 시 업로드 후 plot에 연결. 이모지·그라디언트 선택 UI는 폴백 설정으로 유지
- [ ] `PlotCover` 일원화 — cover_image_id 있으면 `<img>`(alt=플롯 이름), 없으면 이모지+그라디언트. 홈 카드·프로필 헤더·채팅 아바타·대화 목록·위저드 미리보기 전부 이 컴포넌트 경유
- [ ] 시드 플롯 12개는 변경 없음(이모지 유지 — 폴백 경로의 상시 검증 겸)

## 테스트

- [ ] 통합(docker DB) — 업로드: 정상 webp 저장·2MB 초과 413·**가짜 확장자(매직 바이트 불일치) 400**·비로그인 401 / 서빙: content-type·캐시 헤더·없는 id 404 / 플롯 연결: 본인 이미지 성공·타인 이미지 id 400
- [ ] E2E 시나리오 추가 — 위저드에서 이미지 첨부 → 홈 카드·프로필에 썸네일 표시 → 미첨부 플롯은 이모지 폴백 유지

## 구현 노트

- 클라이언트 재인코딩이 1차 방어(용량 축소 + EXIF 등 메타데이터 제거), 서버 매직 바이트 검증이 2차.
  업로드 원본은 서버에 도달하지 않는다(재인코딩 결과만 전송).
- `<img>`에는 width/height 지정으로 레이아웃 시프트 방지, `loading="lazy"`(홈 그리드).
- 이미지 응답은 immutable 캐시라 교체 개념이 없다 — 교체가 생기면 새 id 발급(현재는 수정 없음이라 무관).
- 실서비스 전환점(README 한계에 명시): 오브젝트 스토리지+CDN, 업로드 검수/신고, 이미지 교체.

## 완료 기준

- 이미지 올린 플롯이 홈·프로필·채팅 아바타·대화 목록에 썸네일로 표시, 미첨부는 이모지 폴백
- 큰 파일(2MB+)·비이미지 파일 거부가 사용자 에러 메시지로 안내됨
- "테스트" 섹션 전부 통과(`pnpm test` + `pnpm e2e`)

## 검증 방법

- `pnpm test` + `pnpm e2e` — 완료 기준에 포함

- `pnpm typecheck && pnpm build`
