# T6 — 오피스 실데이터화

- 상태: **완료** · 브랜치: `feature-office-db` · 의존: T4(usage_events)·T2(admin) · 커밋 계획: 2개 — 유저·제재 / 대시보드 합산
- 설계 근거: [server-design.md](../server-design.md) §5(화면 전환)·§6(실사용 지표), 확인 포인트 B·C

## 목표

유저 관리가 실제 가입 유저를 다루고 제재가 효력을 가진다. 대시보드·비용의 활동 지표에
실사용(usage_events·실가입)이 시드 지표와 합산되어 나타난다.

## 범위

- **포함**: 유저 목록·상세 SQL 전환, 제재 API·세션 무효화, 대시보드·비용 합산, 실험 페이지 DB 조회
- **제외**: 매출·GPU 비용·마진·모델별 차트의 실데이터화(시드 전용 유지 — 확인 포인트 C), 차트 킷 변경(불필요)

## 작업 항목

### 유저 관리·제재 (커밋 1)

- [x] 유저 목록 — RSC + SQL: 검색(닉네임/이메일 ilike), 플랜·상태 필터, 정렬(last_active_at/turns/토큰), 20명 페이징(offset). searchParams 기반으로 전환해 URL 공유 가능해짐. 시드 800 + 실가입 유저 한 목록(실가입 표시 배지)
- [x] 유저 상세 — DB 조회. 턴·토큰은 시드값(users 행) + usage_events 합산으로 표시
- [x] `POST /api/admin/users/[id]/sanction` — status 토글 + 해당 유저 sessions 전체 삭제(즉시 로그아웃). SanctionControls를 API 연결로 교체, "데모: 이 세션에서만 반영돼요" 문구 제거

### 대시보드·비용 합산 (커밋 2)

- [x] 합산 쿼리 — 선택 구간(7/30/90일)을 날짜별로: `daily_metrics`(시드, ~08-31) + 실데이터(그 이후). 실데이터 = usage_events 일별 집계(턴=행 수, DAU=distinct user, 토큰=추정 합) + users 실가입(신규)
- [x] 대시보드 — KPI·DAU 추이·기간 비교가 합산 시계열 기준으로 동작(기존 metrics-utils 입력 형태에 맞춰 변환하면 차트는 무변경)
- [x] 비용 — 처리 토큰 KPI·주간 토큰 스택에 실사용 토큰 반영("추정치 포함" 라벨 — 확인 포인트 B). GPU 비용·마진·원가표는 시드 전용 유지 + "시드 데이터" 캡션
- [x] 실험 페이지 — mocks 직접 import를 DB 시드 조회로 교체(읽기 전용)

## 테스트

- [x] 유닛 — **시드+실사용 합산 함수**: 겹치지 않는 날짜 이어붙이기, 겹치는 날 더하기, 실데이터 없는 구간(순수 시드), 시드 없는 미래 날짜(순수 실데이터), 기간 경계(7/30/90) / 기존 이관분: office `format`(만/억·₩·%·delta null)·`niceTicks`·주간 묶음(자투리 버림)
- [x] 통합(docker DB) — 유저 목록 쿼리: 검색(ilike)·플랜/상태 필터·정렬 3종·페이징(경계·범위 밖 clamp)·시드+실가입 혼재 / **제재**: status 변경 + 해당 유저 sessions 전부 삭제 → login 거부·/api/chat 403, 해제 시 복구 / usage_events 집계(일별 distinct user·턴·토큰 합)
- [x] E2E 시나리오 추가 — 웹에서 모의 채팅 수 턴 → 오피스 대시보드(7일)에서 오늘 턴·DAU 반영 확인 → 유저 검색 → 제재 → 그 계정 로그인 차단 → 해제

## 구현 노트

- 시드 daily_metrics는 08-31에 끝나고 실사용은 09-01부터 쌓이므로 **날짜 겹침이 없다** — 합산은
  사실상 시계열 이어붙이기. 겹치는 날이 생겨도 더하기로 정의(주석 명시).
- 기간 필터의 "기준일"이 시드 TODAY(08-31)에서 **실제 오늘**로 바뀐다 — 화면 헤더의 기준일 표기도 갱신.
- 유저 목록이 서버 페이징으로 바뀌므로 기존 클라이언트 필터 state는 searchParams로 이관(칩·select UI는 유지).
- 800명 시드 유저의 country·tokensByModel 등 기존 표시 항목은 시드 컬럼에서 그대로.

## 완료 기준

- 실가입 유저가 목록·상세에 보이고 검색·필터·정렬·페이징이 시드+실가입 통합 목록에서 동작
- 제재 → 해당 유저 즉시 로그아웃 + 로그인 차단("제재된 계정이에요") + /api/chat 403, 오피스 새로고침에도 유지, 해제 시 복구
- 웹에서 모의 채팅 몇 턴 → 오피스 대시보드의 오늘 날짜 턴·DAU·토큰에 반영, 신규 가입도 반영
- 비용 페이지의 시드 전용 차트에 캡션 표시, 기존 차트 인터랙션(크로스헤어·표 전환) 무변경

## 구현 결과 (2026-09-01)

커밋 2개(유저·제재 / 대시보드·비용 합산). `pnpm test` 189개 + `pnpm e2e` 9개 통과,
`pnpm typecheck`·`pnpm build` 통과. E2E가 매 실행 "웹에서 모의 채팅 → 오피스 대시보드에
합산 표기 → 유저 검색 → 제재 → 로그인 차단 → 해제 → 로그인 복구"를 끝까지 확인한다.

설계 대비 조정한 점:

- **합산 결과를 `MetricPoint`(= DailyMetric + realTokens + hasReal)로 만들었다.** 기존 차트가
  `DailyMetric`을 그대로 받으므로 모양을 유지하되, 실사용 토큰만 별도 필드로 얹었다.
  실사용은 유저의 BYOK 모델이라 `tokens`(모델별 분해)에 섞으면 데이터가 거짓이 된다.
- **주간 토큰 스택에 "실사용(추정)" 세그먼트를 따로 뒀다.** 모델 3색 고정 매핑을 깨지 않으려고
  비강조 회색을 썼다 — 자사 모델이 아니라는 뜻이 색으로도 읽힌다.
- **모델 비중의 분모는 자사 모델 토큰만**으로 뒀다. 실사용을 분모에 넣으면 원가표의 비중이
  "자사 모델 안에서의 비중"이 아니게 된다.
- **기간 전환은 여전히 클라이언트에서 한다.** 서버가 전체 시계열(시드 시작일~오늘)을 한 번에
  넘기고 화면이 잘라 쓴다 — 칩을 누를 때마다 왕복하지 않아 기존 조작감이 그대로다.
  유저 목록만 서버 페이징이라 searchParams로 옮겼다(목록은 800+행이라 클라이언트로 못 보낸다).
- **기준일이 실제 오늘이 됐고**, 실사용이 하루라도 있으면 대시보드 부제에 "시드 지표 + 실사용 합산"을
  표시한다. 비용 화면에는 시드 전용 계열임을 캡션으로 명시했다.
- **날짜 경계는 한국 시간**으로 잡는다(`timezone('Asia/Seoul', created_at)::date`). UTC로 자르면
  한국의 밤 활동이 다음 날로 넘어간다.
- `TokenSplit`이 `MockUser` 대신 모델별 토큰 맵만 받도록 좁혔다 — mocks 타입 의존 제거.

남은 한계:

- **매출·GPU 비용·마진·모델별 차트는 시드 전용**이다(확인 포인트 C 그대로). 실 BYOK 사용은
  자사 모델 원가에 대응하지 않는다.
- 토큰은 전부 **글자 수 기반 추정치**다(확인 포인트 B). 화면에 "추정" 라벨을 붙였다.
- 실험 페이지는 DB 조회로 바뀌었지만 여전히 읽기 전용이다(범위 그대로).
