# Google 로그인 설정 가이드

세타의 구글 로그인은 **선택 기능**이다. `GOOGLE_CLIENT_ID`가 비어 있으면 로그인 화면에서
"Google로 계속하기" 버튼이 자동으로 숨겨지고, 이메일 가입 + 데모 계정 원클릭만으로 모든 기능이 동작한다.
아래는 구글 로그인까지 켜고 싶을 때의 절차다. 코드를 열 필요는 없다.

소요: 약 10분. 구글 계정 하나만 있으면 된다(결제 정보 불필요).

---

## 1. 구글 클라우드 프로젝트 만들기

1. <https://console.cloud.google.com/> 접속 → 상단 프로젝트 선택기 → **새 프로젝트**
2. 이름은 아무거나(예: `theta-demo`) → **만들기**
3. 만들어진 프로젝트가 선택돼 있는지 상단에서 확인

## 2. OAuth 동의 화면 구성

좌측 메뉴 **API 및 서비스 → OAuth 동의 화면**

1. User Type: **외부(External)** → 만들기
2. 앱 정보
   - 앱 이름: `세타` (로그인 시 사용자에게 보이는 이름)
   - 사용자 지원 이메일 / 개발자 연락처: 본인 이메일
3. **범위(Scopes)**: 기본값 그대로 둔다. 세타는 `openid`·`email`·`profile`만 쓰는데
   이 셋은 **비민감(non-sensitive) 범위**라 구글 심사(verification)가 필요 없다.
4. 대상(Audience) 화면에서 **게시 상태**를 확인한다.
   - **테스트 중**으로 두면 "테스트 사용자"에 등록한 계정만 로그인할 수 있다(본인 계정만 쓸 거면 이걸로 충분).
   - 누구나 로그인하게 하려면 **앱 게시(프로덕션)** 를 누른다. 비민감 범위만 쓰므로 심사 없이 바로 게시된다.

## 3. OAuth 클라이언트 ID 발급

좌측 메뉴 **API 및 서비스 → 사용자 인증 정보 → + 사용자 인증 정보 만들기 → OAuth 클라이언트 ID**

1. 애플리케이션 유형: **웹 애플리케이션**
2. 이름: 아무거나(예: `theta-web`)
3. **승인된 리디렉션 URI** — 아래 값을 *정확히* 추가한다(끝에 슬래시 없음).

   | 환경 | 리디렉션 URI |
   | --- | --- |
   | 로컬 | `http://localhost:3000/api/auth/google/callback` |
   | 배포 | `https://<web 배포 도메인>/api/auth/google/callback` |

   로컬과 배포를 동시에 쓰려면 두 줄 다 등록한다. **승인된 자바스크립트 원본은 비워 둬도 된다**
   (토큰 교환이 브라우저가 아니라 서버에서 일어나기 때문).
4. 만들기 → **클라이언트 ID**와 **클라이언트 보안 비밀번호**가 뜬다. 이 두 값을 복사한다.

## 4. 환경 변수 입력

저장소 루트의 `.env`에 붙여 넣는다(파일이 없으면 `cp .env.example .env`).

```dotenv
GOOGLE_CLIENT_ID=1234567890-xxxxxxxxxxxxxxxx.apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=GOCSPX-xxxxxxxxxxxxxxxxxxxx
```

dev 서버를 재시작하면 로그인 화면에 "Google로 계속하기" 버튼이 나타난다.

## 5. 확인

1. <http://localhost:3000/login> 접속 → "Google로 계속하기"
2. 구글 계정 선택 → 동의 → 홈으로 돌아오면 성공. 우상단 아바타가 생긴다.
3. 로그아웃 후 다시 구글 로그인 → **같은 계정**으로 들어와야 한다(계정이 새로 생기면 안 됨).

## 동작 방식 (참고)

- 표준 **authorization code flow + PKCE**를 라이브러리 없이 직접 구현했다.
  - `GET /api/auth/google` — `state`·`code_verifier`를 httpOnly 쿠키에 심고 구글로 리다이렉트
  - `GET /api/auth/google/callback` — `state` 대조(CSRF 방어) 후 서버 간 통신으로 코드를 토큰과 교환,
    `id_token`에서 `sub`·`email`·`name`을 읽어 세션 발급
- 계정 매칭은 3분기다: ① `google_sub` 일치 → 그 계정 ② 이메일 일치 → 기존 계정에 `google_sub` 연결
  ③ 둘 다 없음 → 신규 생성(닉네임은 구글 이름 기반, 중복이면 숫자 접미)
- 구글로 만들어진 계정은 `password_hash`가 비어 있어 비밀번호 로그인이 열리지 않는다.

## 문제 해결

| 증상 | 원인·해결 |
| --- | --- |
| `redirect_uri_mismatch` | 3-3의 URI가 한 글자라도 다르다. 프로토콜(http/https)·포트·경로·끝 슬래시를 그대로 맞춘다. |
| 버튼이 안 보인다 | `.env`의 `GOOGLE_CLIENT_ID`가 비어 있거나 dev 서버를 재시작하지 않았다. |
| "액세스 차단됨: 앱이 확인되지 않았습니다" | 동의 화면이 **테스트 중**이고 로그인하려는 계정이 테스트 사용자에 없다. 테스트 사용자에 추가하거나 앱을 게시한다. |
| "로그인 요청이 만료됐어요" | `state` 쿠키(10분)가 만료됐거나 다른 브라우저로 돌아왔다. 로그인 화면에서 다시 시도한다. |
